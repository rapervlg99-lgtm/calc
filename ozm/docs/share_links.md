# Ссылки для обмена расчётами

Ссылка на расчёт создаётся сразу при входе в калькулятор и обновляется по мере
правок, поэтому её можно отправить коллеге или заказчику — открывший увидит тот
же расчёт и сможет его пересчитать и выгрузить.

Формат — как на `calc.tn.ru`: `https://calc.tn.ru/ozm/?n1792668187385`
(токен идёт прямо в строке запроса, без имени параметра). Запасной вид
`?n=n1792668187385` тоже читается.

## Как это работает

1. **Открытие калькулятора.** Фронтенд смотрит на адрес: если в нём есть токен
   `?n…`, состояние читается из `/api/v1/share/{token}` и восстанавливается в
   форме. Если токена нет — сразу создаётся новая ссылка (`POST /api/v1/share`
   с текущим состоянием) и её токен подставляется в адрес через
   `history.replaceState` (без новой записи в истории).
2. **Правки.** Изменения формы уходят в ссылку с задержкой 800 мс
   (`PUT /api/v1/share/{token}`), чтобы не дёргать сервер на каждое нажатие.
   Записывается только изменившееся состояние: одинаковый снимок повторно не
   отправляется.
3. **«Поделиться».** Кнопка в нижней панели копирует ссылку в буфер обмена
   (если браузер не разрешает — показывает адрес в подсказке панели).
4. **Согласие на обработку данных** при открытии чужой ссылки не
   восстанавливается: каждый пользователь ставит его сам, поэтому расчёт по
   ссылке всегда требует явного согласия перед кнопкой «Рассчитать».

## API

| Метод | Путь | Тело/ответ |
|---|---|---|
| `POST` | `/api/v1/share` | `{"payload": {…}}` → `{"token": "n1792668187385"}` |
| `GET` | `/api/v1/share/{token}` | → `{"token": …, "payload": {…}, "updatedAt": …}` |
| `PUT` | `/api/v1/share/{token}` | `{"payload": {…}}` → `{"token": …}` |

- Токен — «n» + миллисекунды (13 цифр), как в расчётах на сайте; при коллизии
  добавляется случайный трёхзначный хвост.
- Тело — JSON-объект состояния калькулятора (объект, адрес, степень
  долговечности, конструкции и группы, бетон). Сервер его не разбирает и не
  валидирует по полям: формат формы можно менять без миграций.
- Ограничение размера — 256 КБ (`413` при превышении), иначе ссылка
  превратилась бы в файлохранилище.
- Хранение — таблица `calc_shares` (`0015_calc_shares.sql`): `token`, `payload`
  (jsonb), `created_at`, `updated_at`. Ссылки не удаляются по TTL: это
  справочные расчёты, но при необходимости добавим срок жизни.

## Ограничения и безопасность

- Токен — единственный секрет ссылки: кто знает ссылку, тот видит расчёт.
  Поэтому токен длиннее 13 цифр только при коллизии, а поиска «по номеру» нет.
- Персональные данные в расчёт не попадают: только объект, адрес и параметры
  конструкций.
- Приватность: согласие на обработку данных не переносится, а восстанавливается
  только вручную.
- Ссылка живёт, пока жива запись в БД; восстановление после потери базы — из
  бэкапа (как и расчёты `calculations`).
