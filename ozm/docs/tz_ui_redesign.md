**Назначение документа:** единое задание для Claude Design (макет) и Claude Code (реализация во `frontend/`).

## 1. Цель

Спроектировать и внедрить **новый брендированный UI** калькулятора ПТМ ТехноНИКОЛЬ, который:

1. Выглядит как продукт экосистемы TN (nav.tn.ru / фирменный стиль), а не «технический паритет».
2. Сохраняет **полный** функционал расчёта, полей и экспорта.
3. Закрывает пробелы текущего UI относительно `screen_map` / `field_catalog` (см. §5).
4. Удобен специалистам ПТМ на desktop; mobile — usable (не secondary-only).

**Не цель v1 редизайна:** менять формулы, dicts, backend, форматы export payloads, внедрять SSO/OIDC (отдельный трек).

## 3. Контекст продукта (для дизайна)

### 3.1 Что это

Онлайн-калькулятор огнезащитных решений ТехноНИКОЛЬ для стальных (и бетонных) конструкций: ввод объекта и элементов → δпр / толщина / объёмы / массы → ведомость материалов → выгрузка отчёта.

### 3.2 Кто пользуется

- Специалисты ПТМ / проектировщики (основной сценарий: много элементов, точные профили, R, стороны нагрева).
- Менеджеры ТН (оценка материалов на объект, экспорт).

### 3.3 Ключевые сценарии

1. **С нуля:** meta объекта → элементы (профиль ГОСТ или ручные размеры) → расчёт → BOM → Excel/PDF/Word.
2. **Из OCR (если C):** PDF спецификации → правка ОГЗ → «Предзаполнить калькулятор» → доработка → расчёт → экспорт.
3. **Исключения:** АКЗ (ручной ввод), недостижимый R — понятные сообщения рядом с элементом / в результатах, без «тихого» нуля.

### 3.4 Стек реализации (для Code)

- Vue 3 + Vite + TypeScript + Pinia + Vue Router
- Сейчас: кастомный CSS (`tokens.css`, `base.css`); `naive-ui` в зависимостях, **не используется**
- **Решение:** Naive UI + тонкая тема под TN-токены
- Ассеты профилей: `frontend/public/img/roll/*.svg`
- API: Axios → `/api/v1` (прокси Vite)

## 4. Дизайн-направление (задание для Claude Design)

### 4.1 Бренд

| Токен | Значение | Назначение |
|-------|----------|------------|
| Primary | `#E30613` | CTA, акцент, ошибки бренда |
| Text | `#262E3F` | Основной текст |
| Muted | `#353E51` | Вторичный текст |
| Line | `#BDBFC6` / `#EDEDEE` | Разделители |
| Soft bg | `#F4F4F9` | Фоновые зоны панелей |
| Font | Proxima Nova / CeraPRO (fallback Arial) | Как в текущих токенах |

Ориентир: деловой B2B-инструмент ТехноНИКОЛЬ, не маркетинговый лендинг и не «дашборд ради дашборда».

### 4.2 Принципы композиции

1. **Один рабочий экран калькулятора** — сверху вниз: бренд/заголовок → meta → группы/элементы → бетон → результаты → экспорт (см. `screen_map.md`).
2. **Бренд заметен** в header (логотип/название продукта), без перегруза hero-маркетингом.
3. **Плотность данных важнее «воздуха»** — это form-heavy tool; таблицы и поля должны читаться специалистом, не «карточки ради карточек».
4. **Карточки элементов** допустимы как единица редактирования (много полей на элемент); BOM и итоги — таблицы.
5. **Одна главная CTA-группа:** «Рассчитать» + блок выгрузки (или sticky bar с действиями).
6. **Состояния:** loading dicts, calc in progress, empty, error, exclusion — явно в UI.
7. **Desktop-first**, breakpoint ~768: одна колонка, горизонтальный scroll у широких таблиц.

### 4.3 Что нарисовать (Deliverables Design)

Обязательные экраны/состояния в Figma (или эквивалент):

1. Калькулятор — пустой / с 1 элементом / с несколькими группами
2. Калькулятор — результат + BOM + exclusions
3. Калькулятор — ошибка валидации / ошибка API
4. Mobile (~375) — тот же поток
5. (Если scope C) Upload → Processing → ОГЗ-форма (таблица профилей)

Компоненты design system (минимум):

- Header / nav
- Text field, Select, Checkbox, Number
- Coat pills / сегменты покрытия
- Heating sides picker (схема L/T/R/B + иконка профиля)
- Element form block
- Results table, Materials table
- Status / exclusion banner
- Primary / secondary / ghost buttons
- Sticky action bar (опционально)

После макета: заполнить `docs/figma.md` + `docs/figma_assets.json`, экспорт в `frontend/public/figma/`.

### 4.4 Чего избегать

- Фиолетовые AI-градиенты, «saas glow», избыточные glassmorphism
- Декоративные карточки без интерактивной роли
- Перекрытие полей/результатов плавающими стикерами
- Скрытие обязательных полей field_catalog «ради чистоты»

## 5. Функциональные требования и пробелы

Текущий UI ≠ целевой `screen_map`. Редизайн **должен закрыть** пробелы, а не только перекрасить.

| Требование | Сейчас | Цель |
|------------|--------|------|
| Согласие ПДн (`consent`) | Hardcoded `true` | Явный checkbox; без согласия calc недоступен |
| Meta: имя, адрес, степень огнестойкости | Есть | Сохранить; оформление по макету |
| Группы как first-class | Checkbox «группы» + опц. title | Панели групп: title, quantity, add/remove/copy |
| Элементы: профиль, сортамент/dims, frType, R, sides, L, qty, coat, method, primer/enamel, decor | В основном есть | Все поля из `field_catalog`; условная видимость TAIKOR/ОЗМ |
| Бетон / ОЗБ | Нет в UI (mapper умеет `betonAreaM2`) | Панель: площадь м² + R180/R240 |
| Режим расчёта | Auto-recalc ~350 ms | **Кнопка «Рассчитать»**; после первого успеха допустим опциональный auto |
| Таблица результатов по элементам | Только live-итоги на карточке | Таблица: δпр, δ, площадь, объём/масса, exclusion |
| BOM материалов | Нет | Таблица `materials[]` (наименования, объёмы/массы/кол-ва). **Без цен** в v1 UI |
| Trace | Не показан | Collapsible «подробности расчёта» (если `trace` в ответе) |
| Экспорт Excel / PDF / Word | Есть | После успешного calc; disabled без `calcId` |
| Prefill из OCR | Есть | Баннер «предзаполнено…»; подсветка `profileMiss` |

Валидации — как в `ux_inventory.md`. Exclusion-тексты — с бэка, не выдумывать.

## 6. Целевая структура экрана калькулятора

```
[Header: TN brand + название инструмента + nav]
[Banner: prefill / dicts error — при наличии]

[Panel: Объект]
  — наименование, адрес, согласие ПДн, степень огнестойкости здания

[Panel: Группа 1…N]                    ← если группы выкл. — одна неявная группа
  [Element 1…M]
    — title, тип конструкции, профиль (+ SVG), сортамент | ручные dims
    — R, стороны нагрева, длина, кол-во
    — покрытие, метод, primer/enamel/decor (по типу покрытия)
    — inline summary / exclusion после расчёта
  [+ Элемент] [Копировать] [Удалить]
[+ Группа]

[Panel: Бетонные конструкции (опц.)]
  — площадь м², R 180 | 240

[CTA: Рассчитать]   (+ индикатор загрузки)

[Panel: Результаты по элементам]       ← таблица
[Panel: Ведомость материалов]          ← таблица (без цен)
[Export: Excel | PDF | Word]
[Trace: раскрывающийся блок]
```

Mobile: single column; широкие таблицы — horizontal scroll.

## 7. Constraints (жёсткие)

1. **Только `frontend/`** для Code-фазы (layout, компоненты, стили, отображение store). Store contract / типы API не ломать; additive UI-only state допустим.
2. **Не менять** shapes `POST /calc`, `GET /dicts`, `POST /export/{pdf|xlsx|docx}` (`api_contract.md`).
3. **Не менять** формулы, округления, тексты exclusion (`calc_rules_summary.md` + golden).
4. **Не удалять** поля из `field_catalog.md`.
5. Backend / dicts / calc / export — **read-only**.
6. После правок: `npm run build` (и существующие Vitest) проходят.
